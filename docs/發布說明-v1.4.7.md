# v1.4.7：補強 Windows 更新時的檔案占用處理

發布日期：2026-09-30。

## 回報與確認範圍

另一台電腦兩次安裝 v1.4.6，均在以暫存執行檔替換 `QuotaDock.exe` 時遇到 `WinError 5`。下載暫存、停止程序步驟與備份已完成；原回報者確認未勾選唯讀，也未手動以系統管理員啟動 App。

隔離 Windows 測試確認，目標執行檔或檔案控制代碼仍被占用時，可產生相同錯誤。原紀錄不足以確定那台電腦上的實際占用者，因此本版補強已重現的處理缺口並增加診斷，不宣稱已確認原機的唯一原因。

## 修正

- **等待檔案釋放**：針對 Windows 存取／共享鎖錯誤 `5`、`32`、`33`，使用同一份已校驗的暫存檔，在每次替換最多 10 秒內重試。備份與回復也採用相同機制；其他錯誤立即回報。
- **補強程序核對**：Windows CIM 未提供同名程序的執行路徑時，以 Windows 原生程序路徑查詢再次核對。只停止完整路徑相符的程序；仍存活但無法核對時，在替換前中止並顯示 PID，不以檔名猜測後強制關閉。
- **提供占用線索**：持續無法替換時，紀錄暫存與目標檔的唯讀狀態，以及 Windows Restart Manager 提供的相關程序名稱與 PID。此查詢不停止程序、不修改檔案或權限；沒有查到程序時，明確標示無法判定。
- **完整保留失敗原因**：清理暫存檔失敗不再蓋掉原始安裝錯誤；舊版檔案已還原但無法自動重開時，明確顯示重開失敗與原因。

不自動更改唯讀屬性、ACL 或安全軟體設定。若 Windows 持續拒絕替換，仍保留原版與可取得的錯誤資訊。

## 更新方式

1. 從系統匣選「結束」，再重新開啟 App，以重新取得最新版本資訊。
2. 點選 v1.4.7 更新按鈕，等待安裝完成。
3. 若仍失敗，提供新訊息與發生問題那台電腦的 `%LOCALAPPDATA%\CodexUsageWidget\install.log`。

既有指令、設定與 Token 資料沿用原位置。

## 驗證

本版加入原生 Windows 檔案鎖、有限重試、回復、唯讀診斷及程序路徑漏檢的回歸測試。發布流程增加前版與新版正式執行檔的隔離升級驗證；實際執行程序、停止、替換與就緒確認，捷徑與開機設定則使用隔離替身，避免修改驗證機器的使用者設定。

這些測試不等同於原回報電腦已成功升級，仍需以該電腦實際更新結果確認。
